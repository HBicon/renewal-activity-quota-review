门店换新活动参与次数限制

规则不绑定门店，通过活动 ID 集合匹配活动；运行时按门店独立计数。成交计一次，全额退款按原周期冲正。

DECISION SUMMARY

本稿要解决什么

用一套可复用的活动集合规则，对大量且持续新增的门店做统一次数控制，同时保留柜机与 App 的独立入口子额度。

01 / 核心判断

三条规则决定实现边界

配置范围与运行时计数主体分离，是避免逐门店维护的关键。

01

配置不绑门店

规则只维护活动 ID 集合。参与集合内活动的门店自动命中，新门店无需补配置。

新门店自动覆盖
02

成交只计一次

一笔订单成交后计为一次参与，同时更新门店总次数和实际成交入口次数，不重复累加。

一单 = 总次数 +1
03

入口额度是子额度

柜机与 App 分别计数，但都不能突破门店总次数。全额退款时两个维度同步还原。

总次数是硬上限
02 / 规则模型

从配置到计数的完整链路

活动集合决定“哪些活动共用额度”，门店 ID 决定“额度归属于谁”。

2活动唯一归属

3门店运行时匹配

门店无需单独配置

4双维度计数

门店总数 + 柜机/App

HARD LIMIT硬上限

门店总次数

规则内所有活动、柜机与 App 成交订单的合计上限。日额度与月额度同时启用时，两项都必须满足。

  • 按“门店 × 规则 × 周期”独立计数
  • 一条规则下的门店之间不共享额度
  • 未启用表示该维度不限，但不能 0 次配置
ENTRY LIMIT子额度

柜机入口次数

限制该门店通过柜机成交的次数，但不额外增加门店总额度。

  • 支持单日、单月独立配置
  • 达到柜机上限时只拦截柜机
  • 总次数未满时，App 仍可继续参与
ENTRY LIMIT子额度

App 入口次数

限制该门店通过 App 成交的次数，与柜机额度分别统计。

  • 支持单日、单月独立配置
  • 达到 App 上限时只拦截 App
  • 成交后仍占用门店总次数
归属规则

一个活动在同一时间只归属一条指定活动规则

全局规则自动排除已被指定规则覆盖的活动，避免同一笔成交进入两个额度池。指定规则停用后，未被子规则覆盖的活动回落到全局规则。
