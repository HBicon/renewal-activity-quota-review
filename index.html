门店换新活动参与次数限制

规则不绑定门店，通过活动 ID 集合匹配活动；运行时按门店独立计数。总次数与柜机/App 次数均按周期选配，并在进入顾客信息页时前置拦截；提交订单时继续原子冻结。参与数量统一按“冻结中 + 已参与”计算。

DECISION SUMMARY

本稿要解决什么

用一套可复用的活动集合规则，对大量且持续新增的门店做统一次数控制，同时保留柜机与软件分订单归宿次数。

01 / 核心判断

三条规则决定实现边界

配置范围与运行时计数主体分离，是避免逐门店维护的关键。

01

配置不绑门店

规则只维护活动 ID 集合。参与集合内活动的门店自动命中，新门店无需补配置。

新门店自动覆盖
02

成交只计一次

一笔订单成交后计为一次参与，同时更新门店合计与订单归宿对应的柜机/软件次数，不重复累加。

一单 = 合计 +1
03

按订单归宿计数

订单归宿固定为“柜机下单”或“软件下单”。已配置门店总量时形成跨入口上限；未配置时按两个入口各自次数独立执行。

门店总量按需执行
02 / 规则模型

从配置到计数的完整链路

活动集合决定“哪些活动共用次数”，门店 ID 决定“次数归属于谁”。

2活跃占用唯一

3门店运行时匹配

门店合计 + 柜机/软件

CONFIGURABLE LIMIT按需

门店总次数

门店日、周、月总数量均选填；已配置的周期按自然日、自然周、自然月执行，未配置的周期不拦截。规则内所有活动、柜机与软件订单仍合计计数并展示。

  • 按“门店 × 规则 × 周期”独立计数
  • 一条规则下的门店之间不共享次数
  • 日、周、月可分别配置，不强制日 ≤ 周 ≤ 月
DESTINATION LIMIT分归宿

柜机次数

柜机日、周、月次数均选填；未填写则不执行对应柜机限制。门店对应周期总量未配置时，柜机按自身已填次数独立执行。

  • 日、周、月次数可独立填写
  • 达到柜机上限时只拦截柜机
  • 未配置门店日总量时，柜机日次数独立生效
DESTINATION LIMIT分归宿

软件次数

软件日、周、月次数均选填；未填写则不执行对应软件限制。门店对应周期总量未配置时，软件按自身已填次数独立执行。

  • 日、周、月次数可独立填写
  • 达到软件上限时只拦截软件下单
  • 未配置门店月总量时，软件月次数独立生效
归属规则

同一活动只被一条活跃规则占用

活动 ID 必填；9 项次数均选填，但至少填写 1 项。同一活动只能被一条启用中或执行中规则占用，停用规则不占用活动。首次启用、重新启用或新增活动时，系统回溯当前日/周/月历史成交生成期初用量；未配置的门店周期不参与拦截。订单归宿在创建或冻结时固化。自然周按周一至周日、自然月按当月统计，启用后先显示执行中。

03 / 次数示意

按日周期试算门店总量或分入口次数

运营内部试算，用来说明门店总量留空时柜机与 App 如何按各自次数独立生效，并预览进入顾客信息页时的拦截文案；不面向门店端。

DEMO PARAMETERS

规则参数

示意器仅演示日周期和拦截结果。门店日总数量留空时，柜机与 App 按各自日次数独立限制；命中限制时模拟“进入顾客信息页”被拦截并展示对应入口文案。前置校验不占次数，真实提交订单仍需原子冻结校验。

04 / 配置设计

运营只维护活动集合与次数

页面不提供门店选择器。规则自动应用于命中活动的所有现有及新增门店，并支持批量导入和操作日志。

SAVE CHECKS

保存前校验

  1. 01活动 ID 必填；9 项次数均选填，但至少填写 1 项
  2. 02活动必须存在且属于换新活动类型
  3. 03同一活动仅能被一条启用中/执行中配置占用
  4. 04每个已填写的门店或入口次数按对应周期独立执行
  5. 05门店周期总量未配置时，按柜机/App 已填次数独立控制
  6. 06次数限制服务异常时严格阻断，不放行
  7. 07批量导入任一行失败则整批不导入
  8. 08创建、编辑、启停和导入记录操作日志
  9. 09首次启用、重新启用和新增活动必须完成期初初始化
  10. 10门店端不展示冻结中、已参与或剩余次数
  11. 11进入顾客信息页前校验；App 次数耗尽提示“APP端办单限量开启，请移步柜机端办理。”
  12. 12柜机继续提示“活动数量已用完，请选择其他活动参与”，提交订单仍执行原子冻结
05 / 前端拦截

进入顾客信息页前先拦住

App 与柜机使用不同提示；前置校验只做资格判断，提交订单时仍执行原子冻结，避免并发穿透。

APP ORDER FLOW

App 办单校验路径

  1. 01
    选择换新活动

    识别门店、活动、入口与订单归宿，匹配次数规则。

  2. 02
    点击进入顾客信息页

    先执行前置次数校验；命中限制时不进入页面。

    新增拦截点
  3. 03
    通过后填写顾客信息

    校验结果不冻结次数，退出或返回后再次进入需重新校验。

  4. 04
    提交订单原子冻结

    若期间次数被其他订单占用，提交仍会失败，不允许超限成交。

只读校验，不是占用

前置校验不创建冻结记录、不改变参与数量；最终可用性只以提交订单的原子冻结结果为准。
